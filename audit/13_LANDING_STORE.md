ламає перший контакт із рекламою (важкі картинки, мертві лінки, зламана «сторінка

## 1. Швидкість лендингу на мобільному

### 1.1 Реальний вимір із прод-домену

`performance.getEntriesByType('navigation'|'resource')` на `https://sixtio.vercel.app/`:

```

telegram.org/js/telegram-web-app.js                    228 ->  416      (cross-origin, 0)
i18n.js?v=43                                           229 ->  366   36 444 B
theme.js?v=43                                          229 ->  284    3 316 B
theme.css?v=43                                         229 ->  338    4 222 B
fonts.googleapis.com/css2?family=Inter...              425 ->  546    1 042 B   <-- @import
```

### 1.2 Вага сторінки

```
index.html   raw   6 505 B   gzip  2 721 B
i18n.js      raw 115 241 B   gzip 34 838 B   <-- 81% усього критичного шляху
theme.js     raw   7 268 B   gzip  2 948 B
theme.css    raw  11 259 B   gzip  3 782 B
------------------------------------------
критичний шлях, gzip                43 052 B
```

### 1.3 Картинки

**Їх немає взагалі.** `ls *.png *.jpg *.svg *.webp` → порожньо; hero — чистий CSS
(`index.html:22-40`, radial-gradient + 2 div-крапки + keyframes). Тобто найдорожчої
статті ваги лендингу тут просто не існує, і оптимізувати нічого. Це ✅.

### 1.4 Шрифти — LAND-4 (P2)

```css
/* theme.css:11 */
@import url('https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&display=swap');
```

`@import` усередині CSS — найгірший спосіб підключити вебшрифт: браузер не бачить
його в HTML, тому відкриває з'єднання до `fonts.googleapis.com` **лише після** того,
як завантажить і розпарсить `theme.css`. У вимірі вище це видно буквально:
`theme.css` закінчився на **338 мс**, Google Fonts стартував на **425 мс**. Далі
той самий ланцюг повторюється до `fonts.gstatic.com` за самим `.woff2`.
`preconnect` до цих доменів у кореневих сторінках **немає** (у `clarity-app/index.html:7-9`
він, іронічно, є).

Пом'якшує ситуацію `display=swap` у тому ж URL: текст малюється системним шрифтом
одразу, тож **LCP на шрифт не чекає**. Ціна — FOUT і невеликий CLS від різниці метрик.

### 1.5 Порядок скриптів — LAND-4 (P2)

```html
<!-- index.html:7-10 — жоден не має defer/async -->
<script src="https://telegram.org/js/telegram-web-app.js"></script>
<script src="i18n.js?v=43"></script>
<script src="theme.js?v=43"></script>
<link rel="stylesheet" href="theme.css?v=43" />
```

Однаково на всіх 11 сторінках. Перший у черзі — **сторонній** домен: власні
DNS + TCP + TLS (≈3 RTT), і поки він не приїде, не малюється нічого. За ним —
`i18n.js` (36 КБ gzip) блокуючим тегом, хоча на лендингу з нього потрібні лише
`idx_thesis`, `idx_sub`, `idx_start`, `idx_hello`.

### 1.6 Вердикт по LCP < 2.5 с

Прямого виміру на throttled 4G у мене немає (§7 #1), тому — розрахунок від
виміряного ланцюга, з явними припущеннями Lighthouse Slow 4G (RTT 150 мс,
~200 КБ/с):

| Етап | Оцінка |
|---|---|
| DNS+TCP+TLS + TTFB + HTML (2.7 КБ) | ~570 мс |
| `telegram-web-app.js` — власний хендшейк, блокує рендер | ~1100–1200 мс |
| own-origin JS+CSS (43 КБ) паралельно | ~930 мс |
| FCP (текст системним шрифтом) | **~1.2–1.4 с** |
| LCP (`.thesis` / `.wordmark`) | **~1.3–1.6 с** |

**Висновок чесний: бюджет 2.5 с ви, найімовірніше, проходите** — саме тому, що на
сторінці немає жодної картинки. LAND-4 — це не «повільно», це **~600–800 мс, які
лежать безкоштовно**: `defer` на `i18n.js`/`theme.js`, `<link rel="preload">`
на шрифт замість `@import`, `preconnect` до `telegram.org` і `fonts.gstatic.com`.
Це не блокер запуску.

## 2. OG / Twitter / favicon / title — LAND-6, LAND-8

### 2.1 Що є насправді

Виконано на живій сторінці:

```
metaCount: 2
metas:     ["charset", "viewport"]
links:     ["stylesheet -> https://sixtio.vercel.app/theme.css?v=43"]
```

Grep по всіх 11 HTML:

```
grep -riE 'property="og:|name="twitter:|name="description"|rel="canonical"|rel="icon"|apple-touch-icon|theme-color' *.html
=> NONE FOUND IN ANY HTML
```

Прод-перевірка:

```
/favicon.ico -> 404  (text/plain, "The page could not be found NOT_FOUND arn1::…")
```

Тобто: **нуль** og/twitter/description/canonical/theme-color, **нуль** іконок.

### 2.2 Але прев'ю для шарингу — працює

І це важливо для пріоритету. Реферальні лінки будуються **не** на веб-домені:

```js
// api/_lib/referrals.js:23
return `https://t.me/${BOT_USERNAME}?startapp=${REF_PREFIX}${telegramId}`;
```

А `t.me` віддає власну картку — перевірено на `https://t.me/Sixtiobot`:

```
og:title       "Sixtio"
og:description "Your AI matchmaker. Real connections by psychological compatibility — not swipes."
og:image       https://cdn4.telesco.pe/file/WZ8PDfqellZjYbghr4x_… .jpg   (аватар бота є)
twitter:card   summary
```

**Тому LAND-6 — це P2, а не P1**: у реальному шляху шарингу (реферали, Telegram Ads,
«скинь другу») картку малює Telegram, і вона нормальна. Проблема залишається лише
там, де хтось поділиться прямим `sixtio.vercel.app` — і в favicon, який видно в
кожній вкладці та в in-app браузері.

### 2.3 LAND-8 (P3) — `title_index` не існує

Коміт `b2dce98` локалізував заголовки сторінок. Лендинг **пропустили**:

```
index.html:6         <title>Sixtio</title>                       <-- без data-i18n
matches.html:6       <title data-i18n="title_matches">…</title>
onboarding.html:6    <title data-i18n="title_onboarding">…</title>
…усі інші 9 сторінок — з data-i18n
```

І ключа теж немає: `i18n.js:24-28` (uk), `:393-397` (en), `:742-746` (ru) містять
`title_feed/matches/match/chat/conversation/profile/settings/onboarding/privacy` —
`title_index` немає в жодній мові. Тобто це не «забули додати атрибут», а прогалина
в словнику; `npm run i18n` її не ловить, бо ключ ніде не запитується.

## 3. 404, редіректи, HTTPS, канонікал

Усе перевірено на проді через `fetch()`:

| Шлях | Статус | Що віддається |
|---|---|---|
| `/no-such-page-xyz` | **404** | `text/plain`, `The page could not be found NOT_FOUND arn1::5j5dt-…` |
| `/favicon.ico` | **404** | те саме |
| `/robots.txt` | **404** | те саме |
| `/terms.html` | **404** | те саме (див. LEG-1, Фаза 7) |
| `/waiting.html` | 200 | легасі-редірект `<meta refresh>` + `location.replace('matches.html')` — працює |
| `/index.html` | 200 | `no-cache, no-store, must-revalidate` |
| `/privacy.html` | 200 | те саме |

**LAND-5 (P2).** Дефолтна 404 Vercel — це `text/plain` без стилів, без мови, без
кнопки «на головну», зі службовим ідентифікатором регіону і запиту в тілі. Для
платного трафіку, який може прийти на застарілий/друкарський лінк, це повний
мертвий кінець. Фікс — `404.html` у корені + `"cleanUrls"` / `"rewrites"` у
`vercel.json` (зараз у `vercel.json` немає жодного `redirects`/`rewrites`/`cleanUrls`).

**HTTPS / www:** домен `sixtio.vercel.app` — HTTPS примусово, HSTS від Vercel,
розщеплення `www`/non-`www` не існує, бо кастомного домену немає. **Не проблема.**

**Канонікал:** `/` і `/index.html` обидва віддають 200 з однаковим тілом, `rel="canonical"`
немає. Для SEO це дубль, але SEO тут не є каналом — Mini App не індексується
осмислено. **P3, разом із LAND-9** (`robots.txt` немає → нічого не закрито; для
dating-домену варто закрити хоча б `/api/`).

**LAND-7 (P2) — домен.** Реклама вестиме на `*.vercel.app`. Для категорії dating
частина рекламних мереж (і Phase 7 / LEG-9) вимагає верифікованого рекламодавця й
власного домену; безкоштовний піддомен платформи — часта причина відмови модерації
і просто нижча довіра в креативі. Кастомний домен — це ~30 хв роботи, зробити **до**
подання креативів.

## 4. Форма / CTA: чи доходить лід

Це найважливіший розділ фази, і тут два реальні дефекти.

### 4.1 LAND-1 (P1) — помилка збереження анкети ковтається

```js
// onboarding.html:515-529
api('/api/profile-info', {
  gender: profileData.gender, seekingGender: …, goal: …, age: …,
  city: …, interests: …, values: …, bio: …
}).catch(function(e){
  console.error('profile-info save failed', e);     // <-- і все
}).then(function(){
  typingEl.remove();
  startPsych();                                     // <-- йдемо далі, ніби зберегли
});
```

І фінальний крок так само:

```js
// onboarding.html:748-764
api('/api/profile', {}).then(function(profile){ … })
  .catch(function(){
    typingEl.remove();
    renderFallbackCard();      // намальована «заглушка» замість Цифрового двійника
    addContinueButton();       // і кнопка «Продовжити», ніби все гаразд
  });
```

**Наслідок.** Будь-яка транзієнтна помилка (401 через прострочений `initData`,
504 від `maxDuration: 30`, обрив мережі в метро) означає: людина чесно пройшла
**14 кроків**, побачила картку, натиснула «Продовжити» — і на сервері немає нічого.
Ані користувач, ані ви про це не дізнаєтеся.

**Чому це невидимо у воронці.** У `api/_lib/events.js:13-23` весь набір подій —
дев'ять штук:

```js
START, ONBOARDING_COMPLETE, FIRST_LIKE, FIRST_MATCH,
RETURN_D1, RETURN_D3, RETURN_D7, PAYWALL_OPEN, PURCHASE
```

Між `start` і `onboarding_complete` лежать усі 14 кроків і **жодної події** — ні
проміжної, ні події помилки. На дашборді ви побачите «4000 стартів → 1000 профілів»
і не зможете відрізнити нормальний відвал від тихо зламаного збереження.
*(Суміжне з Фазою 8, але сам проковтнутий `catch` там не фігурує — це нова знахідка.)*

**Гроші.** При 4 000 стартів/добу (прогноз Фази 10) кожен 1% збоїв = **40 оплачених
лідів на добу в нікуди**, і жодного сигналу.
**Фікс:** показати помилку + «Спробувати ще» замість тихого `console.error`,
додати подію `onboarding_step` з номером кроку. **~0.5 дня.**

### 4.2 LAND-2 (P1, і P0 для не-Telegram каналів) — немає гейта поза Telegram

Перевірено наживо у звичайному браузері (не в Telegram), прод:

```
GET  https://sixtio.vercel.app/onboarding.html   -> 200
title: "Sixtio — знайомство"
видимий текст: "Крок 1 з 14", кнопки "Чоловік" / "Жінка" / "➤"

POST https://sixtio.vercel.app/api/me            -> 401
```

Тобто сторінка **не блокується**: людина бачить робочий інтерфейс, обирає стать,
іде далі — і кожен запит мовчки 401-иться, а завдяки LAND-1 онбординг це проковтне
і доведе її до фейкової картки в кінці.

Перевірок на середовище в коді немає — скрізь лише м'яке `var tg = window.Telegram && window.Telegram.WebApp;`
(`onboarding.html:131`, `index.html:84`) і `initData: (tg && tg.initData) || ''`
(`onboarding.html:230`). Жодного `if (!tg) → показати «Відкрий у Telegram»`.

**Коли це стріляє.** Якщо ви крутите **тільки Telegram Ads** — ніколи: посилання
завжди `t.me/…`. Щойно з'явиться Meta / Google / TikTok / QR на офлайні / пост у
блозі — **100% кліків цього каналу помирають тут**. Тому пріоритет умовний, і
рішення тут продуктове: або гейт, або свідомо тільки Telegram Ads.
**Фікс:** екран «Відкрити в Telegram» з кнопкою на `https://t.me/Sixtiobot/app`
при `!window.Telegram?.WebApp?.initData`. **~2 год.**

### 4.3 Кінцевий пункт ліда

Простежено до кінця: `/api/profile-info` → `users` (Supabase) → `/api/profile`
(`api/profile.js:49` `generateProfile`) → `profiles` → `track(ONBOARDING_COMPLETE)`
(`profile.js:70`) → синхронний `runMatching` (`profile.js:95`).
Окремої «форми ліда» / CRM / email тут немає за задумом — кінцевий пункт це БД,
і він коректний. Проблема не в маршруті, а в тому, що збій маршруту не видно (LAND-1).

### 4.4 ✅ Одне зроблено краще, ніж на сервері

```js
// onboarding.html:231-232
var controller = ('AbortController' in window) ? new AbortController() : null;
if (controller) setTimeout(function(){ controller.abort(); }, 25000);
```

Клієнт має таймаут 25 с під `maxDuration: 30`. Сервер таймаутів не має взагалі
(SCALE-4, Фаза 10) — тут клієнт акуратніший за бекенд.

## 5. Захист від спаму в формах — INFO-3 ✅

Реклама справді притягує ботів, тому це перевірялося окремо. Публічної форми,
яку можна засабмітити без Telegram, **не існує**:

- 11 із 12 ендпоінтів вимагають `initData` з HMAC-підписом
  (`api/_lib/telegram.js:22-24`: `createHmac('sha256','WebAppData').update(botToken)` →
  порівняння `hash`). Підробити без бот-токена неможливо — це сильніше за будь-яку капчу.
- 12-й, `api/geo.js`, неавтентифікований, але лише відлунює гео-заголовки й **не
  торкається БД** — засмічувати нічим.
- Поверх цього — `api/_lib/ratelimit.js:22-35`: `ai_heavy` 6/хв + 40/год,
  `photo` 8/хв, `write` 60/хв, `read` 120/хв.
- Зворотний зв'язок іде командою `/feedback` у бот, тобто теж через Telegram-акаунт.

Капча не потрібна і була б регресом UX. **Єдине зауваження** — обмеження
in-memory і fail-open (SCALE-5, Фаза 10), але це про вартість AI, а не про спам форм.

відмовка: у Telegram немає ані процесу рев'ю, ані форми Data Safety, ані стану
«pending review».

### 6.2 Копірайт лістингу — зроблено правильно

`scripts/setup-bot.mjs` ставить усе, що Telegram дозволяє локалізувати, у трьох мовах:

| Поле | Метод | Мови | Доказ |
|---|---|---|---|
| Назва | `setMyName` | нейтральна | `setup-bot.mjs:41,106` |
| Підзаголовок (він же текст у share-картках) | `setMyShortDescription` | en(default)/uk/ru | `:43-47, 112` |
| Опис на екрані START (це і є ефективне привітання) | `setMyDescription` | en/uk/ru | `:50-75, 113` |
| Меню команд | `setMyCommands` ×2 скоупи | en/uk/ru | `:80-102, 118-121` |

Дефолт = **англійська** як міжнародна база, uk/ru — явні оверрайди (`:110`). Команди
ставляться і в default, і в `all_private_chats` — з коментарем, чому саме (`:114-117`:
Desktop рендерить автокомпліт лише з другого скоупу). `/delete` свідомо прихована з
меню, `/stats` — owner-only. Це акуратна робота, тут правити нічого.

Перші два меседжі несуть суть — вимога «перші 2 екрани несуть меседж» виконана
текстово: підзаголовок = позиціонування («AI-сваха, не свайпи»), опис = три буліти
(інтерв'ю / глибока сумісність / приватність) + CTA (`setup-bot.mjs:52-58`).

### 6.3 Чого немає

- **Скриншотів / демо-відео Mini App** у репозиторії немає (жодного `.png/.jpg`).
  Каталог `t.me/apps` при поданні їх вимагає — чи подані, з репо не видно (§7 #3).
- **ToS у профілі бота не вказано** — `setup-bot.mjs` не викликає нічого для
  Terms/Privacy URL, а `/terms.html` віддає **404** (перевірено). Це той самий
  **LEG-1 (P1)** з Фази 7; тут він фіксується як **прогалина «сторінки в сторі»**,
  бо Telegram очікує ToS для Mini App із платежами.
- **uk/ru описи** з веб-сторінки `t.me` не видно (вона віддає default) — §7 #4.

### 6.4 INFO-2 ✅ — «версія в сторі = версія реклами» неможливо порушити

```json
// vercel.json:8-19
{ "source": "/(.*)\\.html", "headers": [{ "key": "Cache-Control",
  "value": "no-cache, no-store, must-revalidate" }] },
{ "source": "/",            "headers": [{ … те саме … }] }
```

HTML ніколи не кешується, спільні ассети — `?v=43` + `no-cache, must-revalidate`.
Реклама веде на `t.me/Sixtiobot/app` → `web_app.url` → завжди поточний прод.
Класу багів «реклама веде на стару версію» тут **не існує**, і стану «білд на рев'ю»
теж. ✅

### 6.5 LAND-3 (P1) — зворотний бік тієї ж медалі

Саме тому, що прод оновлюється миттєво, **немає жодного бар'єра між `git push` і
живим трафіком**: CLAUDE.md фіксує «No build / typecheck / lint / **CI**», Vercel
авто-деплоїть `main`, staging-оточення немає, процедури відкату — теж.

Під час активної кампанії на 10 000 кліків/добу зламаний пуш означає години
спаленого бюджету без жодного алерту (зовнішнього моніторингу теж немає).
**Фікс (~0.5 дня):** GitHub Action, що на PR ганяє `npm test` + `npm run i18n` +
`node --check`; заборона прямого пушу в `main` під час кампанії; записаний в
`CLAUDE.md` рецепт відкату (Vercel → Instant Rollback).

## 8. Що вже зроблено добре (не чіпати)

1. **Нуль картинок на лендингу** — hero намальований CSS (`index.html:22-40`).
   Найважча стаття ваги просто відсутня; саме тому LCP і вкладається.
2. **`display=swap`** у Google Fonts URL — текст не чекає на шрифт, LCP не заблокований.
3. **Профіль бота повністю налаштований і перевірений наживо** — назва, аватар,
   підзаголовок, опис, `/app`, share-картка з `og:image`.
4. **Лістинг у трьох мовах** із продуманим дефолтом (en) і двома скоупами команд —
   `scripts/setup-bot.mjs` це рідкісно акуратний файл.
5. **Розсинхрон версій неможливий** — `no-store` на HTML + `?v=` на ассетах.
6. **Захист від ботів криптографічний** (HMAC `initData`), капча не потрібна.
7. **HTTPS/HSTS від Vercel**, `www`/non-`www` розщеплення не існує.
8. **Легасі-URL не 404-ить**: `waiting.html` коректно редіректить на `matches.html`
   і `<meta refresh>`, і JS-ом (подвійний запобіжник).
9. **Клієнтський таймаут 25 с** на всіх запитах онбордингу (`onboarding.html:231-232`).
